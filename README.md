# mini_license_plate_recognition — 카메라 번호판 인식

USB 카메라 영상에서 **자동차 번호판을 찾고(감지) → 따라가고(추적) → 글자를 읽는(인식)** GUI 프로그램입니다.

- 카메라 쪽은 완성되어 있습니다: 카메라 검색·해상도 선택·스펙 저장, 렌즈 왜곡 분석·보정, 가이드선, 초점 도우미, 캡처
- 인식: 카메라/영상 입력 → 번호판 감지(**YOLO11s**) → 추적(화면 ID) → 글자 인식(**EasyOCR 한글**) → 여러 번 읽어 글자 자리별 다수결로 번호 고정 → 결과 화면·캡처
- 모델은 `app\models\plate_models.py` 에 등록되어 있고, 인식 설정 창에서 고릅니다 (아래 "모델").

## 실행

Anaconda 환경 `physical_ai` (Python 3.11) 를 씁니다.

```bat
run.bat                                    :: 콘솔 창 없이 실행 (지난번 카메라·해상도)
pythonw main.py --camera 1 --size 640x480  :: 카메라 번호·해상도 지정
pythonw main.py --mode max_fps             :: 최고 프레임 (max_quality = 최고 화질, request = 기본 1920x1080)
pythonw main.py --video D:\영상\road.mp4    :: 영상 파일로 시작 (감지기가 있으면 바로 재생)
pythonw main.py --detector YOLO-v1s --reader EOCR_RAW   :: 모델 키 (기본: YOLO-v1l + EOCR_KR)
```

- **[⚙ 카메라 설정] / [⚙ 인식 설정]** 을 누르면 메인 창 오른쪽에 **별도 창**이 뜹니다. 다시 누르거나 창의 X 를 누르면 닫힙니다(설정은 유지). 두 창을 함께 열어 두고 눌러 보며 시험할 수 있습니다.
- 시작할 때는 카메라 영상만 띄우고 기능은 모두 꺼져 있습니다. 인식은 **[▶ 인식 시작]** 또는 **I** 키.

| 입력 / 상태 | 영상에 보이는 것 |
| --- | --- |
| 카메라, 인식 꺼짐 | 카메라 영상 (보정 화면이면 왜곡 제거) + 카메라 정보·가이드선·초점 도우미 |
| 카메라, 인식 켜짐 | 인식 결과(번호판 박스·번호·노란 ID) 위에 같은 카메라 정보·가이드선. 인식 정보 줄은 오른쪽 아래 |
| 영상 파일 | 인식 결과, 아래 재생바 (클릭 점프·드래그) |

**보정 화면(U)이 켜져 있으면 인식도 왜곡을 편 영상으로 합니다.**

### 카메라 설정 창

| 묶음 | 내용 |
| --- | --- |
| 카메라 | 카메라 목록, 해상도 목록(기본 / 최고 프레임 / 최고 화질 / 지원 해상도 전체), [새로고침] [스펙 다시 측정] [캡처] |
| 렌즈 왜곡 분석·보정 | [분석 D] [자동 인식 A] [자동 보정 C] [보정 화면 U] [초기화 R] [캡처로 보정 K] [보정값 저장] [체커보드 이미지 저장] |
| 가이드선 | [가이드선 G], 종류 7가지 (V): 전체 / 정사각 격자 / 촘촘한 격자 / 3분할 / 중심·동심원 / 대각선 / 체커보드 |
| 초점 (수동 렌즈) | [초점 도우미 F] [피킹 P] [피킹 감도] [최고값 초기화] + 선명도 요약 |

- 카메라는 **이름**으로 구분해 스펙을 `camera_profiles.json` 에 저장합니다. 처음 보는 카메라는 스펙을 먼저 잽니다(30초~1분).
- 보정값은 카메라별 `calibration_<이름>.json`. 그 카메라를 열면 자동으로 불러옵니다.
- 카메라 캡처(Space)는 `captures\camera\` 에 원본 PNG. **[캡처로 보정]** 은 여기서 현재 해상도와 같은 최근 캡처를 최대 10장 씁니다 (체커보드를 찍은 캡처).

## 처리 흐름

```
카메라 (CameraStream 스레드, 최신 프레임, 보정 화면이면 왜곡 제거) ─┐
                                                                   ├─ RecognitionPipeline 스레드
영상 파일                                                          ─┘   번호판 감지 → 추적 (IoU + 등속 예측, 화면 ID)
                                                                        → 감지가 끊긴 번호판은 번호판 영상으로 따라감
                                                                        → 읽는 중인 번호판만 잘라서 선명도 확인 (흐리면 건너뜀) → (보정) → 글자 인식
                                                                        → N번 읽으면 자리별 다수결로 번호 고정 → 결과 이미지 → (캡처 저장 스레드)
```

### 화질·추적 유지 (`plate_enhance.py`, `tracker.py`)

| 기능 | 하는 일 | 기본 | 시간 |
| --- | --- | --- | --- |
| 흐린 프레임 건너뛰기 | 잘라낸 번호판의 선명도(높이 32 px 로 맞춘 라플라시안 분산)를 재서, 그 번호판이 가장 선명했을 때의 50% 보다 흐리면 읽지 않음. 다수결은 선명도로 가중 | 켬 | 0.2 ms/장 |
| 대비 보정 / 선명화 | 글자 인식 직전 CLAHE / 약한 언샤프 마스크. 학습형 초해상도는 글자를 지어낼 수 있어 쓰지 않음 | 켬 (단순 합성 시험에서는 효과 없었지만 종합 시험의 저대비·초점 흐림에서 효과, 2026-11-20 기본 켬) | 0.9 ms/장 |
| 고정 후 추적 유지 | 고정된 번호판은 감지가 30 프레임까지 끊겨도 유지. 끊긴 프레임은 직전 번호판 영상을 예상 위치 둘레에서 찾아 박스를 이어 감 (템플릿 매칭, 반쯤 가려진 박스로는 본보기를 바꾸지 않음, 예상 위치에서 많이 벗어나면 버림). 가림에서 나와 일부만 보이는 번호판도 중심 거리로 같은 추적에 붙임 | 켬 | 1~2 ms/프레임 |
| 낮은 감지로 잇기 | 감지 기준을 0.1 로 낮춰 받고, 0.25 미만 감지는 이미 추적 중인 번호판을 잇는 데만 씀 (ByteTrack 방식, 새 번호판은 만들지 않음) | 켬 | — |
| 번호로 ID 되살리기 | 추적이 끝났다가 300 프레임 안에 같은 번호가 읽히면 이전 화면 ID·고정값을 그대로 씀 (글자를 다시 모으지 않음). 되살릴 후보가 있으면 새 ID 는 첫 글자를 읽을 때까지(최대 10 프레임) 기다렸다 붙임 | 켬 | — |

- 가장 확실한 흐림 대책은 카메라 노출 시간을 줄이는 것 ([카메라 설정]). 소프트웨어로는 이미 사라진 글자 정보를 되살릴 수 없음.

- 카메라 입력은 처리가 카메라보다 느리면 중간 프레임을 건너뛰고 항상 **최신 프레임**을 처리합니다.
- 추적(`app\models\tracker.py`, 학습 불필요): 방향 상관없이 중심 이동 속도로 다음 위치를 예상해 IoU 로 짝짓습니다. 화면 가장자리에 걸려 일부만 보이는 번호판은 다 보일 때까지 읽지 않습니다. 큰 박스 안에 80% 이상 들어간 작은 박스는 같은 번호판의 중복으로 봅니다.
- 글자 고정: 못 읽은 프레임(빈 글자)은 세지 않고, 읽은 글자가 N개(기본 5) 모이면 가장 많이 나온 글자로 고정합니다(같으면 신뢰도 합이 큰 쪽). 다 읽기 전에 화면 밖으로 나가면 모은 만큼으로 고정합니다.
- 번호판 글자(한글)는 맑은 고딕으로 그립니다.

## 모델

`app\models\plate_models.py` 에 등록되어 있습니다.

| 키 | 종류 | 내용 |
| --- | --- | --- |
| `YOLO-v1s` | 번호판 감지 | YOLO11s 번호판 감지 `models\plate_yolo\license-plate-finetune-v1s.pt` (19 MB). conf 0.25, **입력 1280**, GPU 에서 TensorRT FP16 엔진이 있으면 그것을 씀 (없으면 PyTorch fp16). 1080p 감지 TensorRT 약 6 ms (PyTorch 약 9 ms) |
| `YOLO-v1l` (기본) | 번호판 감지 | 같은 저장소의 큰 모델 `license-plate-finetune-v1l.pt` (51 MB). 2026-11-20 기본으로 바꿈 (TensorRT 로 v1s PyTorch 보다 빠름). 엔진이 없으면 PyTorch 로 약 11~19 ms 라 `python export_trt.py` 를 먼저 실행하는 것을 권장. 먼 번호판을 더 잘 찾음 (5·8 m 정면 12종 감지 15/24, v1s 12/24), TensorRT 약 8 ms (PyTorch 약 11~19 ms). 인식 설정 창에서 고름 |
| `EOCR_KR` (기본) | 글자 인식 | EasyOCR 한글+영어. 번호판 글자만 허용, **한국 번호판 형식**(`12가3456`, `123가4567`, `서울12가3456`, 외교 `외교001001`, 구형 이륜차 `서울강남가1234`)에 맞을 때만 읽은 것으로 침. 지역명이 한 글자만 틀리면 고침(`서문12…` → `서울12…`) → 틀린 읽기가 다수결에 덜 섞임. 두 줄 번호판은 위 줄부터 이어 붙임 |
| `EOCR_RAW` | 글자 인식 | EasyOCR 결과 그대로 (형식 검사 없음, 다른 나라 번호판·시험용) |

- **YOLO 가중치 출처**: Hugging Face [morsetechlab/yolov11-license-plate-detection](https://huggingface.co/morsetechlab/yolov11-license-plate-detection) (다운로드 약 8만 회, **AGPL-3.0**). 여러 나라 번호판(Roboflow 데이터셋)으로 학습된 모델이라 한국 번호판 전용은 아닙니다. 크기 n/s/m/l/x 가 있고, 받은 것은 s 와 l (기본 l).
  - 받을 때 확인한 것 (2026-11-20): SHA256 이 Hugging Face 값과 같음 (`95e50c25…2381`). `.pt` 는 불러올 때 코드가 실행될 수 있는 형식이라 불러오기 전에 안을 검사함 → `ultralytics`·`torch` 모델 클래스와 `collections`, `set` 만 있고 위험한 호출 없음. (Hugging Face 는 ultralytics `.pt` 전부에 '주의' 표시를 붙임)
  - 다른 크기를 쓰려면 같은 저장소의 `license-plate-finetune-v1?.pt` 를 `models\plate_yolo\` 에 넣으면 목록에 `YOLO-v1n`, `YOLO-v1m` … 으로 자동 추가됩니다.
  - 다시 받기: `python -c "from huggingface_hub import hf_hub_download as d; [d('morsetechlab/yolov11-license-plate-detection',f'license-plate-finetune-{k}.pt',local_dir='models/plate_yolo') for k in ('v1l','v1s')]"` → 이어서 `python export_trt.py`
- **TensorRT**: `python export_trt.py` 로 `models\plate_yolo\<이름>_1280.engine` (FP16) 을 만들면 앱이 다음 실행부터 자동으로 씁니다 (로그에 `TensorRT FP16` 표시, 없으면 `PyTorch FP16`). 모델마다 2~4 분 걸리고, 엔진은 만든 GPU·TensorRT 버전(10.16)에서만 동작합니다 — 다른 PC·드라이버 업데이트 뒤에는 `--rebuild`. 엔진은 1280x1280 정사각 입력이라 PyTorch(1280x736 직사각)와 박스가 조금 다르지만, PyTorch 를 정사각으로 돌리면 결과가 같고 감지 수도 비슷합니다 (아래 시험 기록). 글자 인식(EasyOCR)은 모델 두 개 + 입력 크기가 바뀌어 TensorRT 로 바꾸지 않았습니다.
- ultralytics 가 없는 패키지를 스스로 설치하지 않게 `YOLO_AUTOINSTALL=False` 로 둡니다 (`plate_models.py`).
- **EasyOCR 가중치**: 처음 쓸 때 `%USERPROFILE%\.EasyOCR\model\` 에 자동으로 받습니다 (`korean_g2.pth`, `craft_mlt_25k.pth`, 이 PC 에는 이미 있음).
- 한국 번호판 인식률을 더 올리려면 한국 번호판 데이터(Roboflow 등)로 YOLO 를 미세 조정한 가중치를 `models\plate_yolo\` 에 넣으면 됩니다.

## 이 PC 의 카메라

- 0번 "EShare Virtual Camera"(가상), **1번 "Global Shutter Camera"** = ELP-U3GS05B10C-IB8 5MP USB 글로벌 셔터, 수동 초점 렌즈(오토포커스 불가).
- **호환성 시험 (2026-11-20, `python camera_compat_test.py`, USB 3.0 연결)**: 지원 모드 18개 모두 정상
  - **최고 화질 MJPG 2592x1944 38.4 fps / 최고 프레임 MJPG 2048x1536 59.7 fps** / 1920x1080 MJPG 60.0 fps (11-13 측정과 같음)
  - YUY2: 2592x1944·2560x1440 35 fps, 2048x1536 50 fps, 1920x1080 이하 60 fps
- **USB 2.0 로 잡히면 큰 모드가 안 됨**: 같은 날 앞서 USB 3.0 포트에 꽂았는데도 윈도우 장치 위치가 `ACPI(HS08)`(USB 2.0 선)로 잡혀 있었고, 1920x1080 이상이 1 fps·검은 화면, YUY2 큰 모드는 카메라가 최대 1 fps 로 알려 옴. 다시 꽂아 `ACPI(SS05)`(SuperSpeed)로 잡힌 뒤 정상. 화면이 검거나 느리면 케이블을 끝까지 다시 꽂고 확인:
  `Get-PnpDeviceProperty -InstanceId <카메라 InstanceId> -KeyName DEVPKEY_Device_LocationPaths` → `SSxx` 면 USB 3, `HSxx` 면 USB 2
- **40 fps 로 묶이는 문제 해결**: DSHOW 로 연 뒤 게인 값을 한 번 '읽기만' 하면 60 fps, 읽지 않으면 약 40 fps (1920x1080: 39.5 → 60.0). `app\models\camera.py` 의 `wake_frame_rate()` 가 열 때마다 읽음 (값은 바꾸지 않음).
- 호환성 시험은 [카메라 설정] → **[호환성 시험 (스펙 다시 측정)]** 버튼으로도 할 수 있습니다 (모드마다 약 3초, 끝나면 사용 불가 모드를 메시지로 알림).

### 번호판 인식 시험 결과 (2026-11-20, 합성)

**처음 앱(YOLO 입력 640)에서 한국 번호판을 거의 못 찾은 원인 = 감지기 입력 크기.** 1920x1080 영상을 640 으로 줄이면 번호판이 너무 작아짐. 글자 인식(EasyOCR)은 정답 위치만 주면 대부분 읽음. → **2026-11-20 앱 감지 입력을 1280 으로 바꾸고 v1l 추가.**

| 감지 설정 | 한국 번호판 12종 x 4조건 감지 | 인식(형식 검사) | 감지 시간 |
| --- | --- | --- | --- |
| v1s 입력 640 (처음 앱) | 8/48 | 5/48 | 8.4 ms |
| **v1s 입력 1280 (11-20 TensorRT 전까지 기본)** | 34/48 | 22/48 → 형식 확장 후 25/48 | 10.9 ms |
| v1n 입력 1280 | 38/48 | 28/48 | 9.7 ms |
| v1m 입력 1280 | 29/48 | 20/48 | — |
| **v1l 입력 1280 (지금 기본)** | 40/48 | 27/48 | 15.7 ms |

거리·각도 한계 (fx 1536 기준, 4개 번호판 중 감지+정확히 읽은 비율이 75% 이상인 범위)

| 조건 | 입력 640 (처음) | 입력 1280 (지금) |
| --- | --- | --- |
| 정면 거리 | 약 3 m (번호판 폭 267 px) | **약 6 m (133 px)** |
| 좌우 각도 (5 m) | 못 찾음 | 45° 까지 |
| 위아래 각도 (5 m) | 못 찾음 | 30° 까지 |
| 기울기 (5 m) | 못 찾음 | 30° 까지 |
| 가로 흐림 (5 m) | 못 찾음 | 5 px 까지 |
| OCR 만 (정답 위치) | 정면 12 m (67 px), 좌우 45° 까지 | 같음 |

- 종류별 (v1s 입력 1280): 일반·영업용(택시·택배)·렌터카·전기차·건설기계는 잘 찾음, 구형 녹색·외교·법인 연두색이 약함
- 글자 형식 검사(EOCR_KR)가 외교(`외교 001-001`)·이륜차 구형(`서울강남 가1234`) 형식을 못 받아들이던 것을 형식 확장으로 해결 (아래 시험 기록). 렌터카 `허` 는 형식 검사판이 맞게 읽고 RAW 는 `히` 로 틀림
- 합성 장면(맑은 고딕, 단순한 차체, 렌즈 휨 없음) 기준이라 실제 성능은 실제 사진·카메라로 확인 필요. 거리는 fx 1536 (보정 파일 값, 영상 너비 x 0.8 로 둔 값) 이 맞을 때만 맞음 — 번호판 폭 px 로 보면 됨 (거리 m ≈ fx x 0.52 / 번호판 폭 px)

### 종합 시험 결과 (2026-11-20, 합성, `plate_stress_test.py`)

번호판 12종 x 움직임 8가지 = 96장면 (번호판 108개), 장면마다 120 프레임. 조건을 일부러 어렵게 섞어서 절대 성공률은 낮음 — **설정끼리 비교**용.

| 설정 | 맞게 고정 | 틀린 번호로 고정 | 화면 ID 1개로 끝까지 | 보이는 동안 박스 표시 |
| --- | --- | --- | --- | --- |
| 이전 (화질·추적 유지 모두 끔) | 30/108 (28%) | 6 | 38/65 | 21% |
| **기본 (지금 앱)** | 33/108 (31%) | 5 | **55/66** | **36%** |
| 기본 + 대비·선명화 보정 | **40/108 (37%)** | **3** | 57/66 | 36% |

- **추적 유지는 효과가 큼**: ID 가 하나로 유지되는 번호판 58% → 83%, 박스 표시 21% → 36%. 멈췄다 출발+흔들림에서 맞게 고정 9 → 11/12, ID 1개 4 → 10/12
- **보정(대비·선명화)은 어려운 화질에서 효과가 있음** (단순 합성 시험 `plate_enhance_test.py` 에서는 효과 없었음): 저대비 6 → 11/27, 초점 흐림 1.5 에서 4 → 8/28, 어두움 12 → 14/29, 틀린 고정 5 → 3. 처리 시간 차이는 거의 없음. → 2026-11-20 기본 켬으로 바꿈
- **가장 큰 한계는 감지**: 보이는 동안 박스 표시가 36% 뿐 (모션블러·흐림·각도에서 감지기가 놓침). 대각선 0/12, 가로 지나감 1~2/12, 두 대 교차 3~4/24. 감지기 추가 학습이 필요
- 틀린 고정은 대부분 **8자리 번호의 한 자리를 빠뜨려 7자리 형식으로 읽음** (`123가4567` → `12가4567`, 비스듬한 장면). 둘 다 올바른 형식이라 형식 검사로 걸러지지 않음. 그 밖에 `허` → `하`, 외교 `001001` → `001007`
- 다 보인 뒤 고정까지 중앙값 22 프레임 (세 설정 같음). 감지 32 ms/프레임은 다른 작업(다운로드·장면 생성)과 같이 돌아 느려진 값 (평소 7~11 ms)
- 결과 `results\plate_stress_20261120_140939`
